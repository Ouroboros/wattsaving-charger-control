# WattSaving 充电机控制（个人项目，非官方）

一个以 TypeScript 编写、编译成静态网页的 Bluefy / Web Bluetooth 控制界面。只在 `wattsaving-charger-control/` 内开发；原微信小程序不作修改。

## 目前实现

- `index.html`：真机控制 / 模拟评审两个独立模式。模拟模式绝不发送 BLE 指令；真机模式没有模拟状态。
- `src/protocol.ts`：从旧小程序提取的两套已知报文（授权、状态、开始、停止、电子锁、时钟同步）。
- `src/ble.ts`：设备选择、可用时恢复浏览器已授权的上次设备、通知解析、五位验证码自动授权及设备回执确认。
- `src/main.ts`：真实状态展示和带确认的操作。没有状态或状态过期时禁用充停；失败和断线不会显示“已成功”。
- 不提供预约或“次日 00:00”控制：开始/结束的含义仍未确认；也没有固件升级、改密码、VIN 操作。

**重要：真实充电机和 iPhone / Bluefy 尚未联调。**原小程序有文件头缺失；并非所有机型都一定适用其报文。初次在设备上验证时请保持充电现场可人工断电或使用原控制手段。

## 本地构建

在本项目目录中运行：

```sh
npm install
npm test
npm run build
```

`src/*.ts` 是唯一实现源码；`app.js` 是 **生成的浏览器部署产物**，不是手写 JS 源码。构建后可以直接打开 `index.html` 查看模拟稿。本地 `file://` 下 Bluefy BLE 是否可用没有可靠结论；真实连接用 HTTPS 的 GitHub Pages URL。

## 真机流程

1. 用 Bluefy 打开本站的 HTTPS 地址，点“真机控制”→“选择 / 更换设备”，在蓝牙设备选择器中选择自己的充电机。
2. 等设备通知自动判别协议；无通知时手动选旧版或新版协议。没有判别协议时不发送验证码。
3. 首次输入五位蓝牙验证码。勾选保存后，**只有收到设备确认正确**才将密码按设备 ID 存入 Bluefy 对此站点的本地存储。下次若浏览器支持 `getDevices()` 并保留该站点的授权，会尝试恢复；否则手动重新选择设备。自动输入失败时删除旧密码并要求重新输入。
4. 授权通过后，网页使用旧小程序的同步时钟帧触发设备状态。没有状态/状态超时、设备模式冲突时按钮不可用；开始、停止和解锁都再次询问，并等待设备状态变化确认。

本地保存的密码**不是 iOS 钥匙串**；同源脚本可读取，清除 Bluefy 网站数据会删除，不会写入 GitHub 仓库。切换 GitHub Pages 域名会改变存储作用域。页面无后台服务，设备密码不通过 HTTP 上传。不要往 Git 仓库添加自己的验证码。

## 当前限制与验证

- Web Bluetooth 的 `requestDevice()` 需要用户点击并授权；自动恢复依赖 Bluefy 是否提供 `getDevices()`，没有保证。
- 旧版数字帧和新版 `@%PD` 帧都由旧源码推断；真实设备必须验证服务、特征、MTU 与通知格式。超过设备可写长度的报文不会被擅自拆分。
- 充停判断以最近的设备状态为准；新协议的接受回执不等于充电状态已改变。超时后提示状态未知，不会盲目重发。
- 网站时钟同步帧会影响设备时钟，不是纯只读操作；手动刷新需要确认。
- 记录、管理员密码、即插即充、预约及“次日 00:00”还需设计确认和硬件验证。
