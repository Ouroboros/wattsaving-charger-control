# WattSaving 充电桩控制（个人项目，非官方）

一个以 TypeScript 编写、编译成静态网页的 Bluefy / Web Bluetooth 控制界面。只在 `wattsaving-charger-control/` 内开发；原微信小程序不作修改。

## 目前实现

- `index.html`：只有真机控制页面，没有演示状态或模拟操作。
- `src/protocol.ts`：从旧小程序提取的两套报文（授权、状态、充停、锁控、时钟同步、预约提交/取消及回执）。
- `src/ble.ts`：设备选择、可用时恢复浏览器已授权的上次设备、通知解析、五位验证码自动授权、控制和预约的设备回执确认。
- `src/main.ts`：真实状态展示、带确认的操作及预约表单。没有新鲜设备状态时禁用充停与预约；失败和断线不会显示“已成功”。
- `src/diagnostics.ts`：本地、限量保存连接、协议、认证、状态和指令的结构化日志；页面提供复制、手动选中与清空入口。
- `src/countdown.ts`：把已确认的预约开始时间和当前 iPhone 时间换算成秒级 `HH:MM:SS`；不发送额外 BLE 指令。
- `scripts/build.mjs`、`src/build-info.ts`：构建时注入版本、提交短号和构建时刻；页面按当前 iPhone / Bluefy 的本地时区显示。
- 预约开始时间自动预填**次日 00:00**（iPhone 本地时间），结束方式可选按时长、按电量或自动充满；不会自动提交。没有固件升级、改密码、VIN 操作。

**重要：iPhone Bluefy 上仅观察到短暂 GATT 连接，尚未成功完成服务/特征发现、设备授权及控制验证。**原小程序有文件头缺失；并非所有机型都一定适用其报文。初次在设备上验证时请保持充电现场可人工断电或使用原控制手段。

## 本地构建

在本项目目录中运行：

```sh
npm install
npm test
npm run build
```

`src/*.ts` 是唯一实现源码；`app.js` 是 **生成的浏览器部署产物**，不是手写 JS 源码。构建后用 HTTPS 的 GitHub Pages URL 在 Bluefy 中打开页面。本地 `file://` 下 Bluefy BLE 是否可用没有可靠结论。

页面顶部显示 `版本 v0.1.0 · 提交 <短号> · 构建（本地） <日期和时间> <时区偏移>`；显示和 `app-start` 诊断事件都按当前设备时区换算，不按构建服务器的时区显示。GitHub Pages 工作流会重新构建，因此线上时间是部署产物的构建时间，而非本地提交时间；若脚本仍被缓存，页面会继续显示旧标识。

## 真机流程

1. 用 Bluefy 打开本站的 HTTPS 地址，点“选择 / 更换设备”，在蓝牙设备选择器中选择自己的充电桩。GATT 连接成功后，网页即在此网站的本地存储中记住该设备（此时不保存验证码）；下次若 Bluefy 的 `getDevices()` 能返回这台已授权设备，会尝试直接恢复，不再弹选择器，否则仍需手动选择。
2. 等设备通知自动判别协议；无通知时手动选旧版或新版协议。没有判别协议时不发送验证码。
3. 首次输入五位蓝牙验证码。勾选保存后，**只有收到设备确认正确**才将密码按设备 ID 存入 Bluefy 对此站点的本地存储。自动输入失败时删除旧密码并要求重新输入。
4. 授权通过后，网页使用旧小程序的同步时钟帧触发设备状态。没有状态/状态超时、设备模式冲突时按钮不可用；开始、停止和解锁都再次询问，并等待设备状态变化确认。
5. 在“预约充电”中检查默认的次日 00:00 开始时间，按需修改；选择自动充满、1～12 小时或 5～95 / 99 度。只支持未来 24 小时内的开始时间。点击提交或取消前再次确认；**只有收到匹配的设备回执才显示成功**。设备状态显示预约模式时可修改或取消；无回执、拒绝或断线会提示结果未知/失败，不自动重发。原小程序将 100 度实际编码为 99 度，所以页面只提供最高 99 度。
6. 收到提交成功回执后，当前页面显示 `HH:MM:SS 后开始充电`，每秒按 iPhone 时钟重新计算；修改预约成功后换成新的开始时间，取消成功后清除。断线时仍可显示估算值；刷新页面后不保留。倒计时归零不代表设备已启动，页面会等待设备状态通知。

本地保存的密码**不是 iOS 钥匙串**；同源脚本可读取，清除 Bluefy 网站数据会删除，不会写入 GitHub 仓库。切换 GitHub Pages 域名会改变存储作用域。页面无后台服务，设备密码不通过 HTTP 上传。不要往 Git 仓库添加自己的验证码。

遇到问题时，在页面底部“诊断日志”点“复制日志”；若自动复制失败，点“选中日志”或长按文本手动复制。诊断 v4 记录选择器、GATT 建连、逐服务查询、特征发现及 UUID 表示形式/匹配决策、通知启动、协议识别、密码输入或缓存授权门控、写入与回执，以及失败后的主动断开原因、实际调用 `gatt.disconnect()` 的时机和意外断线事件。Web Bluetooth 的断线事件不能进一步区分设备与系统哪方触发。标准 UUID 的短码与完整形式均能匹配；自定义 128 位 UUID 仅标记为 `custom128`。不记录自由文本错误消息、原始 BLE 帧、验证码或设备 ID。日志最多保留最近 160 条，复制前仍需自行检查文本。点“清空日志”仅删除日志，不删除设备或验证码。如果浏览器不允许网站存储，当前页面的日志仍可复制，但关闭后可能丢失。

## 当前限制与验证

- Web Bluetooth 的 `requestDevice()` 需要用户点击并授权；自动恢复依赖 Bluefy 是否提供 `getDevices()`，没有保证。
- 旧版数字帧和新版 `@%PD` 帧都由旧源码推断；真实设备必须验证服务、特征、可写长度与通知格式。旧小程序连接后尝试 `wx.setBLEMTU(251)`，网页的当前 Web Bluetooth 接口没有对应设置；超过设备可写长度的报文不会被擅自拆分。
- 充停判断以最近的设备状态为准；新协议的接受回执不等于充电状态已改变。超时后提示状态未知，不会盲目重发。
- 网站时钟同步帧会影响设备时钟，不是纯只读操作；手动刷新需要确认。
- 目标设备曾短暂建立 GATT 连接，但服务查询期间断线，尚不能断定服务或特征是否缺失；通知、设备授权及预约回执仍未实机验证。提交成功只表示设备返回接受回执，不保证将来按时开始或停止，首次使用请在设备旁核对。
- 预约不是网页在后台等待到次日 00:00 再发送“开始”；提交时写入充电桩的预约时间和结束条件。倒计时仅是基于本地时钟的提示，不作为设备安全保证，也不会额外存储设备标识或预约时间。非预约的记录、管理员密码和即插即充设置仍未实现。
