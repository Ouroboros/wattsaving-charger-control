# WattSaving 充电桩控制（个人项目，非官方）

一个以 TypeScript 编写、编译成静态网页的 Bluefy / Web Bluetooth 控制界面。只在 `wattsaving-charger-control/` 内开发；原微信小程序不作修改。

## 目前实现

- `index.html`：固定在视口的外框内有“连接”“充电（含预约和本地历史）”“实验”“反馈”“关于”五个标签；仅内容区内部滚动，标签栏占据外框底行。实验 TAB 独立展示被动二进制状态和手动档位试验，未取得设备字段与人工确认时不能发包。
- `src/protocol.ts`：从旧小程序提取的两套报文（授权、状态、充停、锁控、时钟、预约及其回执；另有独立管理员认证与设置回执）。
- `src/ble.ts`：设备选择、可用时恢复浏览器已授权的上次设备、通知解析、五位验证码自动授权、控制/预约/管理员操作的设备回执确认。实验档位另用原始字节写入，只在 `82/01` 回执和后续 `54` 档位上报同时出现时报告双重确认；不把 GATT 写入完成当作设备接受。管理员权限断线即失效，不保存管理员验证码。
- `src/experimental.ts`：隔离的 App `0x23` 字节帧组包、校验、分片解码和被动 `54` 功率/档位字段；不把二进制内容交给旧文本解码器。
- `src/main.ts`：真实状态展示、带确认的操作及预约表单；操作报错会弹框。没有新鲜设备状态时禁用充停与预约；失败和断线不会显示“已成功”。
- `src/feedback.ts`、`src/tabs.ts`：带 iPhone 本地时间的滚动反馈历史、相邻重复消息计数和标签页切换；重复状态通知的反馈计数最多约每 30 秒重绘一次，不增加 BLE 请求。
- `src/diagnostics.ts`：本地、限量保存连接、协议、认证、状态和指令的结构化日志；页面提供复制、手动选中与清空入口。
- `src/countdown.ts`：把已确认的预约开始时间和当前 iPhone 时间换算成秒级 `HH:MM:SS`；不发送额外 BLE 指令。
- `src/history.ts`：按设备区分的本网页充电状态观察和已获设备回执的预约操作，保存到当前浏览器网站数据；不读取微信本地记录、不生成虚构订单号。
- `scripts/build.mjs`、`src/build-info.ts`：构建时注入版本、提交短号和构建时刻；页面按当前 iPhone / Bluefy 的本地时区显示。
- 预约开始时间自动预填**次日 00:00**（iPhone 本地时间），结束方式可选按时长、按电量或自动充满；不会自动提交。权限管理提供独立管理员验证、即插即充、静音（仅新版）、修改两类验证码、连接认证方式（仅本网站）和新版 FF03 特征可用时的无感配对窗口。没有固件升级或 VIN 管理操作。

**重要：iPhone Bluefy 真机已确认服务/特征发现、设备通知与缓存验证码获设备接受；充停、预约、实验档位写入以及二进制 `82/54` 仍未经旧设备真机验证，充电中断线原因未知。**原小程序有文件头缺失；并非所有机型都一定适用其报文。初次在设备上验证时请保持充电现场可人工断电或使用原控制手段。

## 本地构建

在本项目目录中运行：

```sh
npm install
npm test
npm run build
```

`src/*.ts` 是唯一实现源码；`app.js` 是 **生成的浏览器部署产物**，不是手写 JS 源码。构建后用 HTTPS 的 GitHub Pages URL 在 Bluefy 中打开页面。本地 `file://` 下 Bluefy BLE 是否可用没有可靠结论。

“关于”标签显示 `版本 v0.1.0 · 提交 <短号> · 构建（本地） <日期和时间> <时区偏移>`；显示和 `app-start` 诊断事件都按当前设备时区换算，不按构建服务器的时区显示。GitHub Pages 工作流会重新构建，因此线上时间是部署产物的构建时间，而非本地提交时间；若脚本仍被缓存，页面会继续显示旧标识。

## 真机流程

1. 用 Bluefy 打开本站的 HTTPS 地址，在“连接”标签首次点“选择 / 更换设备”授权充电桩。GATT 连接成功后网页记住设备；本页断线后点“一键连接上次设备”直接复用设备对象，不弹列表。重新打开页面时会自动尝试恢复，也可点同一按钮重试；这时依赖 Bluefy 的 `getDevices()` 返回已授权设备，若浏览器没有返回，网页无法只凭本地名称或 ID 连接，需重新选择授权。
2. 等设备通知自动判别协议；无通知时手动选旧版或新版协议。没有判别协议时不发送验证码。
3. 首次输入五位蓝牙验证码。勾选保存后，**只有收到设备确认正确**才将密码按设备 ID 存入 Bluefy 对此站点的本地存储。自动登录时显示等待确认的提示，不显示密码框；没有保存验证码或自动输入失败时才显示人工输入框，失败后删除旧密码并要求重新输入。
4. 授权通过后，网页使用旧小程序的同步时钟帧触发设备状态。没有状态或状态超时时充停不可用；状态不满足原小程序条件时可点“开始充电”查看阻断原因，但不发送指令。满足条件时操作再次询问，并等待设备状态变化确认。
5. 在“充电”标签的预约区域检查默认的次日 00:00 开始时间，按需修改；选择自动充满、1～12 小时或 5～95 / 99 度。只支持未来 24 小时内的开始时间。点击提交或取消前再次确认；**只有收到匹配的设备回执才显示成功**。设备状态显示预约模式时可修改或取消；无回执、拒绝或断线会提示结果未知/失败，不自动重发。原小程序将 100 度实际编码为 99 度，所以页面只提供最高 99 度。
6. 在“连接”标签进入权限管理：普通蓝牙验证码认证后，再以独立的管理员验证码验证；只有匹配设备回执通过后才能执行设置。旧协议只支持即插即充和修改验证码；新版还支持静音，以及有 FF03 通知特征时打开无感配对窗口。网页不存管理员验证码，修改管理员验证码后须重新验证；修改蓝牙验证码后删除旧的缓存。系统蓝牙配对及静音效果仍须现场核实，不能把命令回执当成已完成配对。
7. 收到提交成功回执后显示本地倒计时；修改/取消后相应更新。预约时间保存在 Bluefy 当前站点的本地数据里；刷新重连后，只有同一设备再次通知预约模式时才恢复倒计时。不连接或没有预约模式通知，不从本地历史推定设备仍有预约。倒计时归零不代表设备已启动。
8. 「实验」TAB **不会主动查询功率**：App 的 `54` 是设备状态通知，不是查询请求；小程序的 `23 05 08 66 96` 查询的是充电模式，不是功率。只有已连接并授权的当前设备主动上报有效 `54` 时展示档位与原始功率按 App 算法除以 10 的数值，单位尚待核实。若要手动试验档位，须从同一设备 App 实包取得四字节桩编码、一字节枪号，输入后核对完整报文，再确认发送；输入不保存，断线或离开页面清除。App 界面见过 22／7／11／16 kW，但顺序与档位序号对应关系未知；不能按这些数字选档，也不自动重试。

“反馈”标签的设备反馈保留当前页面最近 100 条，按 iPhone 本地时间标记；相邻相同消息合并为 `+N`，重复状态通知通常约每 30 秒刷新一次计数，设备状态仍随通知实时处理。错误弹框不会自动重发任何指令。关闭页面后反馈历史不保留。

本地保存的密码**不是 iOS 钥匙串**；同源脚本可读取，清除 Bluefy 网站数据会删除，不会写入 GitHub 仓库。切换 GitHub Pages 域名会改变存储作用域。页面无后台服务，设备密码不通过 HTTP 上传。不要往 Git 仓库添加自己的验证码。

遇到问题时，在“反馈”标签的“诊断日志”点“复制日志”；若自动复制失败，点“选中日志”或长按文本手动复制。诊断 v5 记录选择器、GATT 建连、逐服务查询、特征发现及 UUID 表示形式/匹配决策、通知启动、协议识别、授权门控、写入与回执、主动断开及意外断线。新增同一次尝试的来源和编号、连接与服务/特征查询耗时、页面可见性、断线前最近一次已收到的状态及其年龄、待确认指令与收包统计、状态变化和状态过期。若在服务发现阶段断线且本页此前没有该设备的状态，日志明确标记状态不可用，不能推断设备当时是否充电。Web Bluetooth 的断线事件不能进一步区分设备与系统哪方触发。标准 UUID 的短码与完整形式均能匹配；自定义 128 位 UUID 仅标记为 `custom128`。不记录自由文本错误消息、原始 BLE 帧、验证码或设备 ID。日志最多保留最近 160 条，复制前仍需自行检查文本。点“清空日志”立即清空诊断和页面反馈，不弹确认框；不删除设备或验证码。如果浏览器不允许网站存储，当前页面的日志仍可复制，但关闭后可能丢失。

## 当前限制与验证

- Web Bluetooth 的 `requestDevice()` 需要用户点击并授权；重新打开页面后的一键恢复依赖 Bluefy 的 `getDevices()` 是否返回先前授权对象，不能仅凭保存的设备 ID 绕开浏览器授权。断线但页面未关闭时可复用本页设备对象。
- 旧版数字帧和新版 `@%PD` 帧都由旧源码推断；真实设备必须验证服务、特征、可写长度与通知格式。管理员设置和无感配对尚无真机回执验证；发现不到 FF03 时网页禁用无感配对，发现到也不能单凭设备回执证明系统已配对。旧小程序连接后尝试 `wx.setBLEMTU(251)`，网页的当前 Web Bluetooth 接口没有对应设置；超过设备可写长度的报文不会被擅自拆分。
- 充停判断以最近的设备状态为准；新协议的接受回执不等于充电状态已改变。超时后提示状态未知，不会盲目重发。
- 网站时钟同步帧会影响设备时钟，不是纯只读操作；手动刷新需要确认。静态分析尚未找到可确认纯读取、具备完整回执解析的 App 独有功率查询报文，因此实验 TAB 只被动解析通知，不发送猜测的查询命令。
- 真机诊断已确认 FFE0/FFE4 通知与 FFE5/FFE9 写入、缓存验证码自动授权、设备接受授权及状态通知；也曾在查询 FF00 期间收到非网页主动发起的断线。网页无法从断线事件判断是哪一方结束连接。充停和预约回执仍需真机测试；提交成功只表示设备返回接受回执，不保证将来按时开始或停止，首次使用请在设备旁核对。
- 预约不是网页在后台等待到次日 00:00 再发送“开始”；倒计时仅基于本地时钟，不作为设备安全保证。本网页会在浏览器网站数据中保存设备标识、状态观察和已确认预约时间以展示历史、在设备再次确认预约模式后恢复倒计时；清除网站数据或点击“清除设备及本地历史”会删除这些记录。微信小程序旧记录仍无法直接读取。管理员设置须独立验证，尚待真机验证。
